# Basalt 博客文章编辑

维护 Basalt 项目的 Notion 博客文章，同时保留作者原意、叙述口吻和文章结构。

## 固定范围

- 博客入口：https://app.notion.com/p/30b9289a3ef080f4a061fc2c81f3133d
- 只处理名为「文章」的数据源：`collection://30b9289a-3ef0-8093-8aaa-000b672a420b`。
- 只修改该数据源内用户明确指定或明确要求处理的文章页面。不要修改「照片」「最近」「友链」数据源，不要改变数据库结构、视图、发布状态、发布时间、封面或其他未要求的属性。
- 用户仅要求审阅、建议或预览时，不写回 Notion。只有用户要求润色、编辑、修改或补全时才更新对应文章。

## 编辑流程

1. 用 Notion MCP 获取目标页面，确认它属于上述「文章」数据源；若无法确认，停止写入并说明原因。
2. 完整阅读标题、正文和现有属性。保留 Notion 的块结构、链接、媒体、代码、书签、引用和其他非正文内容。
3. 润色正文时加载并遵循 `chinese-copyediting` skill，但以本 skill 的规则优先：
   - 修正错别字、搭配不当和明显不通顺的表达。
   - 减少邻近句段中无意的用词重复，可用贴合语境的同义词替换。
   - 只做小范围润色，不扩写论点、不改变事实主张、立场、语气或段落结构。
   - 不在中文与英文、中文与数字之间新增空格；站点 CSS 会负责视觉间距。
   - 不改代码、命令、URL、文件名、标识符及品牌的官方拼写。
4. 仅当下列属性为空或缺失时补全；已有值默认保留：
   - `摘要`：根据全文写一段简洁、自足的中文摘要，准确概括文章主题，不添加正文没有的结论。
   - `标签`：优先从数据源已有选项中选择最贴切的少量标签；现有选项都不合适时，才新增简短、稳定、可复用的中文标签。不要为了凑数添加泛化标签。
   - `路径`：生成简短、语义清晰、可长期使用的 URL slug。使用小写 ASCII 字母、数字和连字符，不带 `/articles/`、首尾斜杠、查询参数或空格；写入前检查同一数据源中是否重复。不要改动已有路径，除非用户明确要求。
5. 将正文润色与缺失属性补全合并为一次范围明确的更新。不要顺带发布文章或触发同步、部署。
6. 更新后重新获取页面，确认正文可读、目标属性已写入、Notion 结构未损坏，并简要报告修改了什么。

## 判断与异常

- 标签或路径存在多种同样合理的选择时，根据标题和正文选择最贴近文章核心的一种，不必为轻微偏好中断工作。
- 文章语义含混、疑似事实错误或专有名词无法可靠判断时，保留原文并向用户指出；不要猜测性改写。
- 若页面不属于目标数据源、权限不足、正文被截断或包含无法安全往返的未知块，禁止覆盖正文；报告阻碍并保留原内容。
